# Semantic security finding applicability

Reviewed 2026-10-07; expires 2026-11-05. Raw CodeQL SARIF and every original high-severity finding remain in CI evidence. Scanner suppression metadata cannot exempt a finding. The assessment is limited to three exact `java/csrf-unprotected-request-type` results with the reviewed rule descriptor, path, handler line and severity. Other rules, paths, locations or severities block.

The Google and GitHub callbacks must accept provider GET redirects. Each validates unpredictable state and its browser cookie, exact provider and expiry, then atomically consumes the record before token exchange or session issuance. PKCE binds the exchange; Google additionally verifies token/nonce claims. Rejected callbacks preserve the pending binding. Eight real PostgreSQL tests cover mismatches, expiry, provider confusion, successful exchange, concurrent/later replay and failed-exchange replay for both providers. Provider HTTP and identity lookup are mocked; production state SQL and session writes execute against PostgreSQL. These tests do not certify live OAuth provider registration.

The administrator report-evidence GET requires current ADMIN plus MFA and changes only access-log metadata. It cannot mutate report/inquiry state or enforcement outcomes. [RFC 9110 section 9.2.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.1) permits incidental access logging for safe methods. `DataExposureIntegrationTest.administratorInquiryEvidenceGetOnlyAppendsAuditAfterCurrentMfa` proves anonymous/non-MFA denial, unchanged domain snapshots and the expected single metadata-only append after an authorized read.

`SAST_APPLICABILITY.json` pins every production and test input plus Maven and verification build inputs, including audit consumers and migrations. Adding, removing or changing any input invalidates the assessment and requires review of a refreshed specification. CodeQL rule descriptor changes and expiry also require reassessment. The backend job parses actual XML testcase elements (excluding logged text, CDATA and comments), verifies the exact named tests and binds their report hashes, specification hash, source commit, workflow run and attempt. The Java analysis job requires that successful backend job and downloads its artifact from the same run. It rechecks every source/test hash and named unskipped passing test, report integrity, commit/run/attempt and a one-hour freshness window, then records the raw SARIF hash with the explicit `not_affected` disposition. Missing or substituted evidence fails closed.

Negative tests in `tests/sast-dispositions.test.mjs` prove that different rules/locations/severities, changed inventories, stale/future/expired evidence, different commits/runs/attempts, changed report bytes and missing/failed/skipped regressions cannot authorize an exception. `tests/sast-security-gate.test.mjs` separately rejects incomplete/failed SARIF, invalid rule/component references and invalid severity, while allowing valid clean reports.

This is a reviewed applicability assessment for this application, not a global query exclusion, scanner suppression, zero-finding claim or external penetration-test result. An actual current-source CI run must pass before release.
