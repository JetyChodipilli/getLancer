# V5.0 rebuild contract

Baseline: main `95ba03da3264d09b9efdeea799b813d7ee9f760c` (V4.9, PR #43). Scope: roadmap S06-B01–B08 / FR-036, FR-037, FR-039, NFR-021 and the supplied V5.0 README. Revision 1, 2026-10-10.

## Architecture

Reuse React/Vinext and Spectral Studio, Spring's typed education releases and existing purchase authority, PostgreSQL lab reservations/outbox/fencing/cleanup and signed operator manifests. No new application dependency or migration is planned. Four original MIT, synthetic, Python standard-library scenarios produce actual local results. Source-only and recorded evidence are available independently of hosted activation. `APP_DATA_AI_ENABLED=false` adds admission and revocation control; it does not replace `APP_LABS_ENABLED` or current provider certification. Production deployment and provider activation are outside this rebuild.

## Curated runtime and material interface

Paths: `labs/data-ai/`, `scripts/build-data-ai-material.mjs`, `scripts/verify-data-ai.mjs`; generated public artifacts live under `public/data-ai/` and are ignored. The runtime owns source and static catalogue, its material builder and focused reproduction tests. The frontend owns `lib/data-ai.ts`, its inspector and tests.

Scenario IDs: `revenue-summary`, `sensor-quality`, `sentiment-inference`, `equipment-inference`. Two deterministic analytics jobs and two original frozen JSON logistic models; no training, pickle, executable model loaders, remote code, files or URLs selected by requests. Each inference case evaluates eight held-out synthetic samples with explicit split/protocol/limitations.

One process has an operator-set UUID `LAB_RUN_ID`, binds to `127.0.0.1` and uses `LAB_PORT`. `GET /health`; form `POST /request` with `runId`, `scenarioId`, `operationId=execute` and allowlisted scenario inputs. Reject wrong identity, unknown/duplicate fields, bad UTF-8, malformed percent encoding, queries, unsupported paths/methods/types, chunked or conflicting framing. Maximum request 8192 bytes, output 4096 bytes, 100 attempts, 300-second lifetime, 90-second idle lifetime, absolute one-second request/header/body deadline. Apply supported OS memory/CPU limits; explain portability limits. No uploads/CORS or arbitrary network access.

Result envelope uses exactly `schemaVersion`, `mode`, `runId`, `scenarioId`, `sourceSha256`, `dataSha256`, `modelSha256`, `evaluationSha256`, `input`, `inputSha256`, `result`, `resultSha256`, `startedAt`, `elapsedMs`. Schema is `getlancer-data-ai-result-v1`; mode is `LOCAL`; hashes are lowercase SHA-256, absent model/evaluation hashes are null. Input is a bounded map of strings. Hash input/result as recursively key-sorted compact UTF-8 JSON; normalize integral floats to integers and round non-integral values to at most six decimal places to preserve Python/JavaScript agreement. Measure actual time, UUID and source/data/model/evaluation bytes.

`result` has exactly `tables`, `metrics`, `prediction`, `evaluation`. Tables (maximum two) have `id,title,columns,rows`; columns have `key,label,unit,type` (`number` or `string`), at most eight; rows at most 32, matching the declared keys and types. Metrics (at most twenty) have `key,label,value,unit`. Prediction is null or `{label,probability}`. Evaluation is null or `{split,protocol,samples,correct,accuracy,limitations}` with correct/samples/accuracy consistency. Values are finite, bounded and small enough to fit the output limit; counts and money use integer units. Give analytics/inference outputs explicit schema and unit descriptions.

Material index: `{schemaVersion:"getlancer-data-ai-index-v1",sourceSha256,archiveSha256,sourceUrl,setup,items}`. Four items have `id,kind,title,summary,outputSchema,inputs,defaultInputs,changedInputs,dataLicense,dataProvenance,dataSha256,modelLicense,modelProvenance,modelSha256,modelFormat,evaluationSplit,evaluationProtocol,evaluationSha256,limitations,recordingUrl`. Kind is `DATA_ANALYTICS` or `AI_ML`. Inputs reuse existing lab input definitions. Model/evaluation fields use null for analytics. Source URL is `/data-ai/source.tar.gz`; recording URL is `/data-ai/recordings/<id>.json`.

Each recording is exactly `{schemaVersion:"getlancer-data-ai-recording-v1",mode:"REPLAY",scenarioId,sourceSha256,dataSha256,modelSha256,evaluationSha256,recordedAt,runs}`. Runs are two actual LOCAL envelopes (default and changed inputs). Do not fabricate replay on a failure. Validate original identities, hash binding, byte limits, time and contextual numeric consistency before showing it. Recordings and source are generated by executing the source. Package a fixed safe inventory with deterministic tar/gzip headers, reject symlinks/foreign paths and verify extracted source in a clean temporary directory. `--verify` checks reproducibility rather than requiring measured timestamps to be deterministic.

The UI at `/labs/data-ai` is an evidence inspector with Source, Recorded execution and Hosted runtime disclosure. Selecting a recorded case changes the evidence shown; it never claims to execute a new input. Local source reproduction performs computation. Use original timestamps/hash labels and accessible tables/charts; no unsupported accuracy claims.

## Education evidence contract

Optional draft object `dataAiEvidence` has exactly: `codeLicense,dataLicense,dataProvenance,dataSha256,modelLicense,modelProvenance,modelSha256,modelFormat,evaluationSplit,evaluationProtocol,outputSchema,limitations,redistributionAllowed,syntheticData,noRemoteCode`. Text/hash fields stay bounded and typed; booleans are real booleans. Save incomplete drafts. New DATA_ANALYTICS/AI_ML submissions require complete code/data provenance, output schema, limitations and affirmative redistribution/synthetic/no-remote-code declarations. AI additionally requires model provenance/hash/licence, `modelFormat=JSON`, split and evaluation protocol. Model fields may be empty for analytics. Other categories reject this object. Preserve historical submitted releases and accepted agreements with no new object; only new submissions enforce it. Freeze valid evidence into new submitted/approved snapshots and accepted purchases.

Public/export/commerce projections allowlist each nested field and exclude private storage keys, unexpected fields, source bytes and academic annotations. Preserve existing private package storage, MFA/CSRF review and paid entitlement authority. Frontend drafts, detail/review and purchase disclosures use the same schema and show historic absence honestly. Extend relevant seed metadata without executing seller uploads.

## Verification and deployment

Operator manifests may declare `resourceClass=GENERAL|DATA_ANALYTICS|AI_ML`. Historic manifests without this field keep their prior behavior; curated scenario IDs and the `data-ai-` namespace still trigger V5.0 policy. Renamed data/AI scenarios remain guarded through their signed declared class. Each class admits at most four uncleaned reservations and 1024 MiB independently; each curated run reserves at most 256 MiB. Existing global and actor quotas/budgets also apply. Disabled/expired/revoked runs close request/event routes and the watchdog fences cleanup; disabling either execution flag never prevents STOP confirmation or releases uncertain reservations early.

Runtime reproduction must prove changed-input effects, independent numeric oracles, malformed/hostile request denials, bounded lifetime/output and clean package extraction. Backend tests prove typed validation, immutability, public privacy, historical compatibility, exact accepted purchase evidence, default-denied admissions, active/queued revocation, confirmed cleanup and independent class memory reservation. Frontend tests prove strict evidence rejection and accessible responsive source/replay/hosted states. Run existing Node, Java/PostgreSQL, browser, build, authorization/database and CI/security checks without weakening guards. Current CI on the final head is required before merge. External hosted/provider gates remain disabled and documented.
