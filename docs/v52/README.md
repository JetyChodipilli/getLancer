# V5.2: measurement and operational release control

Implements the S08 software backlog in the accepted roadmap. A software merge does not close the real deployment and research gates in [LAUNCH_GATES.md](LAUNCH_GATES.md). This phase remains partial until those gates have evidence and owner approval.

- [Implementation contract](CONTRACT.md), [CEO scope review](../../memory/v52-ceo-review.md)
- [Complete requirement mapping](requirements.csv) and [machine-readable inventory](requirements.json): 46 functional and 22 non-functional requirements, explicit primary checks and owner-reviewed deployment gates.
- [Operational evidence and handover](../../ops/v52/README.md)

Operator measurement reuses authoritative records and current administrator MFA. Optional browser observations require analytics consent and a configured backend; browser samples cannot assert genuine payments, provisioned runs or source entitlement. No search text, sensor/request input, token, private brief or email is captured by the new schema. Empty denominators have no rate; illustrative/replay observations do not count as live infrastructure success.

Original material targets are 24 frontend components, 18 native backend labs and twelve projects across four categories. Clean package reproduction and current licence/hash inventory run in CI; source-only examples and software simulations are labelled. Paid material remains governed by existing frozen agreements and merchant configuration, never a public sample ZIP.

Operations surfaces quota, budget, stale-worker and orphan attention with named alerts. The existing admission shutdown, version withdrawal, capability revocation and encrypted restore controls remain authoritative. The runbook rehearses them in disposable infrastructure before deployment approval; rolling back code never rewinds money or revives old capabilities.

Load measurements declare their dataset and environment. Client latency is separate from request-local server timing. The seven-day recorder uses real time, outage samples and explicit admission denominators; its tests only validate the evidence mechanism. Synthetic fixtures cannot certify a production soak.

Validation results and immutable CI/head identity are recorded in VALIDATION.md after verification. Existing legacy UI, manual screen-reader research, production availability, physical hardware and future language/GPU/team scope are not silently certified by automated new-flow checks.
