API CONTRACT — V1
1. Purpose
This document defines the external REST contract for V1. An OpenAPI file may later be generated from or aligned to this contract. Endpoints are versioned under /api/v1.
2. Conventions
Content Type
application/json unless uploading directly to object storage through signed URLs.
Authentication
Browser-first sessions use secure cookies or equivalent secure session strategy. Endpoints below mark whether authentication is required.
IDs
Use UUIDs internally. Public resources should prefer slugs where user-facing.
Timestamps
ISO-8601 UTC.
Pagination
Request:
?page=0&size=20
Response:
{
  "items": [],
  "page": 0,
  "size": 20,
  "totalItems": 0,
  "totalPages": 0
}
Cursor pagination may replace page-number pagination for high-volume feeds later.

4. Authentication Endpoints
POST /api/v1/auth/signup
Auth: Public
Request:
{
  "email": "builder@example.com",
  "password": "...",
  "role": "DEVELOPER"
}
Responses:
201 account created; verification sent
400 validation
409 email already registered
429 rate limited
POST /api/v1/auth/login
Auth: Public
Request:
{
  "email": "builder@example.com",
  "password": "..."
}
Responses: 200, 401, 429.
POST /api/v1/auth/logout
Auth: Required
Response: 204.
POST /api/v1/auth/verify-email
Auth: Public
{"token":"..."}
Must be idempotent after successful verification.
POST /api/v1/auth/password-reset/request
Auth: Public. Always return neutral success to reduce account enumeration.
POST /api/v1/auth/password-reset/confirm
Auth: Public; valid one-time token required.

19. Analytics Events
Prefer server-authoritative events for business outcomes and client-side events for UI interactions.
Do not expose an unrestricted public endpoint that accepts arbitrary business-success events.
20. Rate Limits — Initial Policy
Exact values are configuration, not code constants.
Protect at minimum:
login;
password reset;
verification resend;
inquiry creation;
save/remove spam;
report submission;
admin authentication.
Return 429 with retry guidance where safe.
21. Authorization Matrix
Public product read: Public, Client, Developer, and Admin may read approved public products.
Private draft: Only the owning developer and authorized Admin may read.
Edit product: Only the owning developer may edit; Admin may take moderation actions but should not impersonate normal owner editing.
Developer inquiry: Only the client participant, target developer, and explicitly authorized support/admin staff may access.
Review creation: Only the confirmed client for an eligible completed engagement may create the review.
Admin queue: Admin only.
Every object-level authorization must be enforced server-side.
22. API Compatibility
Breaking changes require new API version or controlled compatibility strategy.
Error codes are stable contracts.
Additive response fields should not break clients.
Database implementation details are never exposed as API contracts.

Implementation addendum — 14 September 2026
PUT /developer/profile accepts optional websiteUrl (public HTTPS), country (ISO alpha-2), timeZone (IANA) and languages (text, max 200). Omitting an optional field preserves its stored value; empty string clears it. These fields are included in approved public builder profiles and moderation evidence. Material edits require re-review.
POST /inquiries/{id}/review and review-token confirmation accept visibility: ANONYMOUS (default) or NAMED. Client workspace alias shares the same validation. Public builder review responses include id and clientName; anonymous reviews return Verified client, named reviews return the inquiry's client name. Email is never returned. Replaying identical review text/rating/visibility is harmless; changing an already-submitted review returns REVIEW_EXISTS.

Implementation addendum — 15 September 2026
DELETE /me initiates account closure and returns 202 with status EMAIL_CONFIRMATION_REQUIRED. The account remains active until the emailed ACCOUNT_DELETION token is confirmed through POST /auth/confirm with decision DELETE. The token expires after 15 minutes; repeated confirmation is idempotent. Confirmation revokes sessions/tokens and hides public content, while final retention/purge remains a staff policy workflow. The sole administrator cannot close this way.
GET /developer/products accepts lifecycleStatus and approvalStatus, validates their enum values, and filters before page/size pagination. totalOwned counts all owner showcases; activeCount is independent of the selected page/filter.
GET /me/saved-products accepts optional ids, a comma-separated list of at most 50 UUIDs, to look up saved state for a visible gallery page. The normal paginated collection remains available when ids is omitted.
GET /products/{slug} includes reviewSummary {reviewCount, averageRating}. These are builder-wide published reviews for confirmed completed, unrestricted inquiries. With no reviews, reviewCount is 0 and averageRating is null. Public and granted-client product responses omit moderationReason; owner and administrator management responses retain it.
POST /inquiries accepts the recommended Idempotency-Key UUID when present. When omitted, the server assigns an internal key and still applies duplicate and rate-limit rules. Reuse a client key for idempotent retries.
POST /reports permits anonymous reports and treats invalid/revoked/expired/suspended sessions as anonymous. Protected endpoints still require an active valid session. Database errors are not converted into anonymous authorization.
