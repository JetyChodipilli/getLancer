5. Active Showcase Slots
FR-SLOT-001
Each approved developer starts with 3 active showcase slots.
FR-SLOT-002
Drafts do not consume active slots.
FR-SLOT-003
Archived products do not consume active slots.
FR-SLOT-004
Archiving an active product immediately frees one slot.
FR-SLOT-005
A developer cannot activate more products than their entitlement.
FR-SLOT-006
An active product remains active after generating a hire.
FR-SLOT-007
Slot capacity must be represented as an entitlement rather than hard-coded into product rows.
FR-SLOT-008
V1.5 may add earned capacity from verified marketplace outcomes.
6. Product Review / Moderation
Developer Flow
Draft
→ Submit
→ Pending Review
→ Approved
   OR Changes Requested
   OR Rejected
Admin review checklist:
Description matches evidence
Category and technology are reasonable
Screenshots are relevant
Live URL is not localhost/private network
No obvious phishing/malware behavior
No obvious copied/stolen work
Contributor role is stated
Confidential/client information is not improperly exposed
Project quality meets platform standard
Trusted-builder auto-publish is deferred.

8.1 Saved Products
FR-SAVE-001
Authenticated clients can save an approved public product for later review.
FR-SAVE-002
A client can remove a saved product.
FR-SAVE-003
The same client/product pair can exist only once.
FR-SAVE-004
Saving a product does not notify the developer by default.
FR-SAVE-005
If a product is archived or suspended, historical saves remain in the client account but the product is clearly marked unavailable and is removed from public discovery.

17. Edge Cases
Product / Slot Edge Cases
User archives product while review is pending
Product is approved but slot capacity is full
User reduces plan capacity later
Product is suspended by admin
Same external live URL used by multiple accounts
Private project has no screenshot due to NDA
Product has contributors but contributor account does not exist
Inquiry Edge Cases
Client never verifies email
Client submits duplicate inquiry
Developer account becomes suspended after inquiry
Product is archived after inquiry
Developer changes availability after inquiry
Client mistypes company/site
Client attempts to spam many developers
Developer marks Hired but client rejects confirmation
Review Edge Cases
Client disappears after completion
Client and developer disagree about completion
Review contains abuse or confidential information
Client wants review identity hidden
URL Edge Cases
Reject or quarantine:
localhost
127.0.0.1
::1
RFC1918/private networks
link-local IPs
cloud instance metadata destinations
file://
javascript:
data: where not explicitly supported

19. Acceptance Criteria Summary
V1 is acceptable when:
Approved developer can publish within slot limit
Client can browse without login
Client can submit a product-linked inquiry
Developer receives and sees inquiry
Hire/completion can be confirmed
Verified review requires confirmed completion
Admin can moderate content
Unsafe demo URL patterns are blocked
Search supports business-problem discovery
Core events are tracked for conversion analysis
